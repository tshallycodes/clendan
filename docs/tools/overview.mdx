# AI Tools

Clendan tools are specialised AI sub-agents. Each tool has a defined role,
a set of capabilities it can execute, and policy rules it must enforce. Tools are
deployed per organisation and configured independently.

## Architecture

Clendan uses a master-subagent model:

```
Financial Orchestrator (Master Agent)
├── Receives all financial events
├── Classifies the event type
├── Routes to the correct tool
└── Tools execute as sub-agents
    ├── Document Intelligence
    ├── AI Accountant
    ├── Spend Control
    ├── AR & Collections
    ├── Risk & Compliance
    ├── Treasury & Cash
    └── ... (all others)
```

Tools never call each other directly. All coordination flows through
the Financial Orchestrator.

## Autonomy Levels

Every tool is configured with one of three autonomy levels:

| Level | Behaviour |
|---|---|
| **Auto** | Executes actions autonomously within your policy thresholds |
| **Approve** | Always requests human approval before executing |
| **Suggest** | Recommends actions but never executes — you confirm manually |

## Available Tools

| Tool | Purpose |
|---|---|
| **Document Intelligence** | OCR and AI extraction for receipts using vision |
| **AI Accountant** | Transaction categorisation and invoice matching |
| **Spend Control** | Expense policy enforcement, hard rules, and burn-rate analysis |
| **AR & Collections** | Invoice urgency classification and chase email drafting |
| **Risk & Compliance** | AML/KYC/GDPR violation detection and structuring analysis |
| **Treasury & Cash** | Cash position monitoring, burn rate, and runway forecasting |
| **Reconciliation** | Bank-to-invoice and bank-to-bill matching with anomaly detection |
| **Revenue Recognition** | ASC 606 / IFRS 15 five-step schedule and journal generation |
| **Credit Underwriting** | Credit risk grading, DTI/LTV enforcement, and adverse action notices |
| **Tax Compliance** | VAT position computation and missing-tax classification |
| **Financial Reporting** | P&L, balance sheet, and cash flow summary with anomaly detection |
| **Payment Runs** | AP bill classification, duplicate detection, and payment routing |
| **Budgeting** | Budget vs. actuals variance analysis and run-rate projections |

## Decision Types

Every tool returns one of the following decision values. The decision type determines whether an approval record is created and what actions are available in the dashboard.

| Tool | Autonomous path | Requires human approval |
|---|---|---|
| Document Intelligence | `auto_approved` | `blocked` (no approval flow — resubmit required) |
| AI Accountant | `auto` | `pending` |
| Spend Control | `auto_approved` | `approval_required`, `blocked` |
| AR & Collections | `auto_approved`, `reminders_required` | `escalation_required` |
| Risk & Compliance | `auto_approved` | `approval_required`, `blocked` |
| Treasury & Cash | `auto_approved` | `approval_required` |
| Reconciliation | `auto_approved` | `approval_required`, `flagged` |
| Revenue Recognition | `revenue_scheduled` | — (confidence gate only) |
| Credit Underwriting | `auto_approved` | `approval_required`, `blocked` |
| Tax Compliance | `auto_approved` | `compliance_review`, `vat_alert` |
| Financial Reporting | `auto_approved` | `approval_required` |
| Payment Runs | `auto_approved`, `duplicates_flagged` | `approval_required`, `blocked` |
| Budgeting | `auto_approved` | `approval_required` |

## Policy Engine

Every tool output passes through the policy engine before any action
is taken. The policy engine is deterministic — same input always produces
the same decision.

Policies are configured per tool per organisation:
- Approval thresholds (amount ranges)
- Verified supplier/vendor lists
- Currency allow-lists
- Restricted fields
- Human override triggers

See [Policy Engine](/platform/policy-engine) for full configuration reference.

## Audit Trail

Every action taken by every tool is written to the immutable audit trail
before the response is returned. If the audit write fails, the operation fails.

Each audit entry contains:
- Tool name and version
- Full input data
- Policy evaluation results (each rule, pass/fail)
- Decision and confidence score
- Actions executed
- Reasoning trace
- Duration

See [Audit Trail](/platform/audit-trail) for details.
