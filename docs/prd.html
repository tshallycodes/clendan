01 Problem

Finance operations in companies remain manual, fragmented, and expensive to scale. Existing AI tools offer suggestions and dashboards — not execution. The gap between "AI recommends an action" and "AI executes the action" is where significant cost and error lives.

66% of AP departments still process invoices manually (2025)
50% of finance teams take 6+ days to close the books each month
94% of finance teams use Excel in their month-end close process
$6+ average cost to manually process a single invoice
9% of AP departments are fully automated with touch-free invoice flow
50hrs average monthly time spent on cash reconciliation alone
Core Problem
Existing tools (Tipalti, Xero, QuickBooks, Ramp) are failing at ERP sync, OCR accuracy, approval audit trails, and cross-system reconciliation. Companies are still hiring humans to fill the gaps. Source: G2/Capterra review analysis, LinkedIn job postings, Ardent Partners 2025.
02 Solution

Clendan is an API platform where companies deploy AI financial workers that run their financial operations autonomously. Finance teams connect their tools once, configure their rules once, and walk away. Workers handle the rest — processing invoices, categorising transactions, reconciling accounts, chasing collections — without requiring human input unless the policy threshold says otherwise.

Core Positioning
Clendan is not a chatbot, dashboard, or analytics SaaS. It is zero-touch execution infrastructure. The finance team's job shifts from executing tasks to supervising autonomous workers — reviewing exceptions, setting thresholds, and approving edge cases. A finance team processing 200 invoices a month manually recovers 80% of that time. The remaining 20% are the decisions that actually require human judgment.
How It Works — One Sentence
An invoice arrives in QuickBooks at 2am → Clendan reads it, checks policy, approves and logs it → the finance manager wakes up and it's already done. They only see it if it needed a human decision.

Each AI worker has a defined role, a set of tools it can call, policies it must enforce, and an autonomy level: auto-execute, request approval, or suggest only.

05 AI Financial Workers
Architecture Model
Clendan uses a master-subagent architecture. The Financial Orchestrator is the master agent — it receives all incoming financial events, classifies them, selects the appropriate sub-agent workers, passes context between them, and manages the full execution chain. Each worker is a specialised sub-agent called as a tool by the Orchestrator. Workers do not call each other directly. All coordination flows through the Orchestrator.
Key Design Principle
Workers never call each other directly. All coordination flows through the Orchestrator. This keeps each worker testable in isolation, replaceable without breaking the chain, and gives the Orchestrator complete visibility over every step. A single incoming invoice can trigger a chain: Invoice Processing Worker → Fraud Detection Worker → Policy Engine → Human Approval API — all orchestrated and logged in sequence.

Each worker is configurable per tenant, versioned, and rollback-capable. Autonomy levels (auto / approve / suggest) are set per worker per tenant.

Financial Orchestrator — Now Live
The Orchestrator is live. It receives financial events via POST /v1/events — the single entry point for all automation. It classifies the event type, selects the appropriate worker, invokes it as a tool, applies policy, writes the audit log, and creates an approval request if the decision exceeds the threshold. External triggers (QuickBooks webhook, Plaid transaction sync, Stripe payment events) all flow through this single endpoint. Workers never fire directly — everything routes through the Orchestrator.
06 Standalone API Tools

Five purpose-built APIs that function independently as products and power Clendan workers internally. API-first, no configuration required, JSON in/out. Each creates an independent revenue stream and a data flywheel that improves model accuracy over time.

Invoice Parser API
POST /v1/parse/invoice
Takes any invoice format — PDF, image, email attachment — and returns structured JSON: vendor, line items, amounts, due date, VAT, PO number. No templates, no configuration. AI extraction only.
↳ Powers: Invoice Processing Worker
Receipt OCR + Policy Check API
POST /v1/parse/receipt
Extracts data from receipt images and validates against company expense policy rules. Returns approved/rejected with structured reason. Policy rules configured per tenant.
↳ Powers: Expense Control Worker
Document Reconciliation API
POST /v1/reconcile
Takes two financial datasets — bank statement and ledger export — returns matched, unmatched, and flagged rows with confidence scores. Directly addresses the 20–50hr/month reconciliation problem.
↳ Powers: Reconciliation Worker, Accountant Worker
Fraud Signal API
POST /v1/fraud/score
Takes a transaction or batch of transactions, returns a risk score with structured reasoning. Low latency, plugs into any payment flow. Sells independently to fintechs and lending platforms.
↳ Powers: Fraud Detection Worker
Contract Data Extraction API
POST /v1/parse/contract
Takes a contract PDF and returns structured data: payment terms, renewal dates, obligations, amounts, counterparty. Sells to legal ops, procurement, and finance teams independently.
↳ Powers: Revenue Recognition Worker, Collections Worker

07 Platform APIs

The core infrastructure APIs that power the Clendan platform. Companies integrate these to deploy, configure, and monitor their AI workers.

  • Agent Builder API — POST /agents — Define role, tools, autonomy level, constraints, model config per worker
  • Tool Registry API — POST /tools/register — Connect external systems: banks, ERP, credit bureaus, payment systems. Each tool has input/output schema, auth method, permissions
  • Execution API — POST /agents/{id}/run — Trigger agent run, receive decision + confidence + reasoning trace + executed actions
  • Policy Engine API — POST /agents/{id}/policy — Define approval thresholds, spending limits, compliance rules, human override triggers
  • Event System — POST /v1/events — Single orchestrator entry point. All financial events route here: invoice_received, transaction_posted, expense_submitted, reconciliation_requested, fraud_check_requested. Idempotent via Idempotency-Key header.
  • Workflow Orchestration API — POST /workflows — Chain multiple agents: accounting pipeline, reconciliation pipeline
  • Human Approval API — POST /approvals/request — Route decisions for human review when risk is high or confidence is low
  • Explainability API — GET /decisions/{trace_id}/explain — Return decision factors, data sources, reasoning trace, model version
Architecture Note
The Tool Registry is the hardest technical component. Auth management, credential rotation, and rate limit handling across banking APIs (Plaid, Codat, banking cores) require dedicated architecture. This must be specced before coding begins — it is not a config file.
08 MVP Scope
MVP Definition
One agent. Two integrations. A working execution and audit loop. The goal of the MVP is a working end-to-end demo that directly beats Tipalti's documented failure points: better OCR, ERP sync that works, and a full approval audit trail.
  • Agent: Invoice Processing Worker only
  • Integrations: QuickBooks (accounting) + Plaid (bank feed)
  • API Tools: Invoice Parser API + Receipt OCR API
  • Policy Engine: Basic rules — approval thresholds, spending limits
  • Human Approval API: Route flagged invoices for review
  • Explainability: Reasoning trace on every invoice decision
  • Dashboard: Minimal control plane — execution log, approval queue, audit trail
  • Multi-tenant: Row-level security from day one — non-negotiable
Explicitly Out of MVP
Credit Underwriting Worker, all other workers, Orchestrator meta-agent, FP&A, budgeting, additional ERP integrations beyond QuickBooks. Add nothing until the MVP demo is clean and a design partner has validated it.

10 Integrations Roadmap

Integrations are the surface area of what Clendan can automate. Each new integration means more of the finance stack runs without human input. Every integration follows the same pattern: connect → webhook → orchestrator event → worker → audit.

Integration Type Events Emitted Priority

NetSuite ERP (Enterprise) invoice_received, reconciliation_requested V3
Xero
UK/ANZ dominant accounting platform. Near-identical build to the existing QuickBooks integration — OAuth 2.0, webhooks, HMAC-SHA256 signature verification, same invoice_received event. Highest priority next integration given the UK market focus. Estimated: 2 days.
Stripe
Every SaaS company runs billing through Stripe. No OAuth needed — API key auth. invoice.created and invoice.finalized fire invoice_received events. charge.succeeded fires transaction_posted events. This removes the biggest manual accounting job for SaaS companies: reconciling Stripe payments against invoices. Stripe customers → vendor mapping handled in integration config.
Excel Add-in (Microsoft Office Add-in)
Finance teams live in Excel. The add-in brings Clendan workers into the spreadsheet as a task pane — select a range of transactions, click "Run AI Accountant", get results written back to cells. Auth via existing API keys (no Clerk dependency). Phase 2: custom Excel functions — =CLENDAN.CATEGORISE(A2:E2). New package: excel-addin/ (React + Office.js). Enables adoption without changing the finance team's existing workflow.

14 Non-Functional Requirements
  • Full audit logging for every action — immutable, timestamped, tenant-scoped
  • Strict tool permission isolation per tenant from day one
  • Encrypted financial data at rest and in transit
  • Deterministic policy enforcement — same input must produce same policy output
  • Explainability required for all agent decisions
  • Rollback capability for financial actions where reversible
  • Decision latency target: 2–5 seconds
  • Multi-tenant isolation: row-level security (Postgres RLS) — no cross-tenant data leakage under any condition
  • SOC 2 Type II readiness by month 9
  • GDPR and UK DPA compliant data handling
